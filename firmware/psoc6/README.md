# PSoC 6 replay firmware

The paper's measured target is a CY8CPROTO-063-BLE board with a Cortex-M4F application core. ModusToolbox generates the dual-core project locally; `mtb/bootstrap.py` connects it to the native-C inference and personalization sources in this directory. The generated workspace and downloaded BSP libraries are excluded from the publication package.

## Setup and build

Install ModusToolbox 3.8. By default the helper looks under `/opt/Tools/ModusToolbox/tools_3.8`; set `MTB_TOOLS_DIR` if your installation differs. From this directory:

```bash
make bootstrap
make getlibs
make build
make check
```

`make bootstrap` creates `mtb/build_workspace/psoc6_dual_core_ecg` using Infineon's `mtb-example-psoc6-dual-cpu-empty-app`, then connects the CM4 application source and include paths. It is safe to rerun. `make check` verifies this integration without changing files. The CM0+ generated by Infineon boots the CM4; the published `mtb/cm4_main.c` starts the ECG replay application.

With a connected board, `make program` builds and flashes the image. The CM4 logs profiling cycles, per-record replay F1, and aggregate F1 at 115200 baud on the KitProg3 virtual serial port, typically `/dev/ttyACM0`. To capture a run:

```bash
python ../../scripts/capture_firmware_benchmark.py --port /dev/ttyACM0 --out ../../results/firmware/local_device_capture.json
```

The included `generated/benchmark_replay.h` contains the one-shot capped replay. It holds the selected ECG windows in flash and is much larger than the model weights. Recreate it after changing support shots, then build and program again; see the commands in the [root README](../../README.md). The exact K=1/5/10 device captures, host references, and UART logs used in the revision are already preserved under `results/firmware/`.

## Implemented scope

- `common/source/backbone_runtime.c`: frozen float32 CNN inference.
- `common/source/personalization.c`: incremental prototype means and 50 full-batch SGD updates of the linear head.
- `app/source/ecg_head_adaptation_app.c`: deterministic benchmark, UART output, and DWT cycle timing.
- `generated/model_params.h`, `head_weight.h`, `head_bias.h`: exported model parameters.
- `app/source/demo_ecg_app.c` and `ui/`: optional graphical demonstration; the benchmark entry point above runs the replay application.

The published timing is measured at 100 MHz. It includes support embedding and head update, and excludes query inference, UART, and replay control. The 5.2 KB flash / 22.2 KB SRAM manuscript figure is a model-centric budget, not the size of the generated board image. Upstream beat detection and INT8/TFLM execution are outside the measured firmware path.
